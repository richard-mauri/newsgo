# NewsGo — architecture

See [AGENTS.md](AGENTS.md) and [DEVELOPMENT.md](DEVELOPMENT.md) for workflow, [README.md](README.md) for operation, and [CURRENT_WORK.md](CURRENT_WORK.md) for the active draft PR.

## Runtime

- `cmd/newsgo/main.go`: service startup, catalog, server settings, listener, graceful shutdown; default `127.0.0.1:8084`.
- `internal/dashboard/`: UI, personal reading pipeline, Homepage account integration, administrator routes, diagnostics and operational settings.
- `internal/feeds/`: feed validation and fetching, URL safety, parsing and article normalization.
- ScraperGo is independent and provides article classifications, clean reading and thumbnails.

## Reading and classification

NewsGo fetches selected RSS/Atom/JSON subscriptions in batches of at most eight. Each eligible article is checked using ScraperGo `POST /api/classify`; only confirmed `article` URLs appear in either normal or RSS metadata-only reading. Homepages, unreadable/unavailable/unknown outcomes, age-filtered articles and entries beyond feed caps are reported in the filtered/unprocessed audit. RSS metadata-only changes the displayed metadata and thumbnail source, not the classifier gate.

NewsGo's shared classification cache is persisted in the settings directory as `classification-cache.json` using atomic, permission-restricted snapshots. At startup, only valid, unexpired classifications are restored, and any rejected or expired entries are removed from the persisted snapshot through atomic compaction. Malformed, oversized and over-capacity cache files fail safely to a cold cache. Entries have absolute expirations at most 12 hours after classification, including across restarts and rebuilds. Normal-operation garbage collection is lazy on writes, without a periodic background cleanup timer. The cache is bounded to 2,048 entries, with expired/earliest-expiring eviction. The default administrator TTL is 720 minutes; a saved setting above 720 minutes is capped to 720 at runtime without rewriting `server-settings.json`. A configured zero disables caching. A cache write failure does not alter ScraperGo eligibility or account data. An existing stored TTL of 60 minutes remains in effect until the administrator changes the setting to 720 minutes. Previously cached absolute expirations are not extended retroactively. Readers can opt out of cache use in Reading Preferences without clearing shared entries. The per-reader Diagnostics view reports cache hits, misses, bypasses, disabled requests, configured TTL, feed durations, classification durations and render durations. ScraperGo has separate upstream caching not included in these counters.

## Homepage-only authentication and account persistence

Homepage provides **all live reader identity and account persistence**. The browser obtains a tab-scoped `#suite_token` handoff from Homepage and verifies it using `https://home.themauris.org/api/session/profile`. The token is removed from the visible URL and retained in `sessionStorage` while the original Homepage session is active, up to twelve hours. Following verified sign-in, NewsGo automatically retrieves the reader's account settings through Homepage's revisioned `/api/storage/newsgo` GET API, applies valid existing account data, and initializes the correct revision for debounced automatic PUT saves. If there is no account record, NewsGo initializes one using local preferences for the same browser user or an empty profile when the last verified browser account belongs to a different user. A failed read or unsupported schema never authorizes overwriting existing data. Profiles remain isolated by Homepage identity. Browser-only preferences remain in browser `localStorage`. The legacy Account Sync panel, Save to account and Load from account buttons are removed. HTTP 409 conflicts suspend writes and retain browser state, with a visible account-status warning. No separate NewsGo token issuance or profile-sync login exists. The page includes a content-derived fingerprint in the `/personal.js` URL to prevent stale script reuse across development builds with the same semantic version. NewsGo shows only Homepage-asserted identity, with no app-specific renewal button or countdown. Homepage's Manage Tokens → Current session panel owns the timer, Renew and Disconnect. NewsGo stores the parent-bound handoff only in its tab. If an HTTPS direct visit to NewsGo has no handoff, it performs a one-time top-level navigation to Homepage's fixed `/launch/newsgo` route. Homepage alone reads the host-only cookie and either issues a new durable, parent-bound handoff in the NewsGo URL fragment or returns `#suite_mode=local` for an absent/expired/revoked parent; NewsGo recognizes the explicit local-only URL fragment for that page visit, preventing an immediate redirect loop while preserving local settings. A later direct visit rechecks Homepage in case the user has since signed in. NewsGo revalidates its profile against Homepage when the locally cached expiration is reached, because the parent may have been renewed while NewsGo remained open. The recovery navigation neither creates nor renews the parent login. A 401 clears the handoff; the server remains authoritative for privilege and per-user storage. NewsGo does not invoke `/api/handoff/extend-session`, `/api/handoff/renew` or `/api/session/renew`. Browser-only access remains functional without a bearer.

NewsGo administrator endpoints `GET/PUT /api/admin/settings` and `POST /api/admin/classification-diagnostic` require server-side verification of the supplied Homepage bearer against Homepage's **fixed** HTTPS session-profile endpoint on every privileged request. The browser sends it in the dedicated `X-NewsGo-Homepage-Authorization` header. The Go verifier requires a valid bearer, a current expiry and the server-asserted `admin` role, with three-second timeout, no redirects and no persistent secret logging. An ordinary Homepage reader cannot administer NewsGo, regardless of browser UI manipulation. Reading Diagnostics is not privileged and remains browser-local.

There is no Server Sync token authentication, `/api/sync` route, separate token CLI, or migration path for old browser subscription formats. Current subscriptions are stored in the single `newsgo.subscriptions.unified.v1` browser registry. Homepage stores the optional account copy. Historical token and profile files, if still present on disk, are unused.

## Operational server settings

`internal/dashboard/settings_store.go` implements a dedicated, mutex-protected `SettingsStore` that reads and writes the existing revisioned `data/server-settings.json` atomically with restrictive file permissions. The CLI flag `-settings-dir` selects the directory (default `data`). Classification timeout/concurrency, per-feed cap, feed cache, classification-cache TTL and image settings use the current settings schema. Saving server settings updates active settings and clears both NewsGo's in-memory and on-disk classification cache. An administrator-saved TTL of zero disables NewsGo classification caching.

## Other diagnostics and safety

The administrator's fresh classification diagnostic is deliberately uncached. The localhost-limited feed-trace endpoint remains available. The client-side Download Article URLs export is placed in the Admin Settings panel, separate from the server settings form, and remains restricted by the browser to a live Homepage administrator session and completed all-subscriptions reading batch. It exports already displayed eligible URLs and does not create a server-side privileged download API.

Publisher URLs and responses are untrusted and subject to existing validation, request limits, timeouts and network safety rules. A browser role label alone is never an authorization decision. `cmd/scrapertrace` independently replays exported URLs through ScraperGo with sequential default operation, optional bounded four-worker concurrency, separate classification/read HTTP status and latency reporting.

## Filtered audit domain grouping (Issue #83)

Within each reason tab, browser-side `renderFilteredArticles` groups the existing filtered audit entries by `publisherScope(article.url)`, not display names or counts from feeds. Each normalized non-excluded domain gets exactly one `setUnifiedDomain(domain,false)` action alongside its count. Unknown hosts are grouped without a destructive action. `setUnifiedDomain` preserves the existing `confirmDomainRemoval` prompt and per-user exclusion/account storage workflow. Classification, counts, per-article links, admin fresh-classification details and the single-feed unsubscribe recommendation remain independent and unchanged. Grouping is presentation-only; no automatic exclusions.

## Cache-miss diagnostics (Issue #85)

The classification stats response includes cache misses split into absent and expired keys, plus miss outcomes for explicit `unknown`, `unavailable`, and invalid/failed upstream requests. The latter three are deliberately noncacheable. A named return and deferred miss accounting ensure failures and indeterminate results are counted once without storing raw URLs or mutating cache entries. The front end sums counts across feeds and displays them in Diagnostics → Latest read. Repeated requests with the same URL can yield repeat misses for noncacheable outcomes; cold/expired counters describe the entry at lookup time, not whether the request eventually produced a successful cache fill. Existing persistence, TTL, capacity, feed classification, and independent ScraperGo behavior are unchanged.

## Pre-classification reader domain exclusions (Issue #85)

The browser submits `excludedDomains:effectiveExcludedDomains()` with each bounded `/api/personal` batch, from the existing browser-local or Homepage-hydrated reader profile. The server validates the list and compares parsed normalized article URL hostnames, including subdomains but not sibling or suffix-lookalike hosts, before age filtering and ScraperGo classification/cache lookup. Matching articles get the existing `publisher exclusion` reason in the filtered audit without a ScraperGo request or a classification-cache miss. The server does not alter stored subscriptions, account data, global classification cache settings, or the feed fetch itself. Exclusion is a presentation/reader preference, not a security control; a caller can elect not to exclude a domain. Other reader clients that omit `excludedDomains` retain the old default behavior. Diagnostics remain request-based and exclude skipped entries from cache-hit-rate denominators.

## Optional Homepage activity telemetry (Issue #89 draft)

`cmd/newsgo/main.go` creates an `ActivityReporter` only when explicitly configured with a URL and per-service secret. The reporter embeds `internal/dashboard/activity.js`, which sends a random tab-scoped identifier and coarse `visible`/`interacted` flags to a same-origin `POST /api/activity/ping`. That endpoint rejects cross-origin requests, unknown JSON, oversized input and malformed IDs, bounds the in-memory tab map to 5,000 and expires tabs after one hour. The reporter counts the rolling 2/5/15/60-minute windows and in-flight `/api/personal` requests, including feed and ScraperGo classification work within the synchronous request lifecycle. It sends only aggregate counts and timestamps to Homepage `POST /api/admin/activity/ingest` every 60 seconds using a server-only private key and fresh replay nonce. It is fail-open and has no authority over NewsGo sign-in or reader output. HTTPS or explicit loopback HTTP collector URL only; strict endpoint path, no credentials in URL and no redirects.

NewsGo does not independently authenticate Homepage users on a telemetry ping, so current `anonymous` means anonymous **or unverified**, rather than a reliable split from signed-in users. No browser-supplied role flag is trusted. Disconnected/scraper-queued work is out of scope and should be measured by ScraperGo's independent reporter. The Homepage dashboard labels a NewsGo reporter as unknown if no fresh report arrives, not idle.
