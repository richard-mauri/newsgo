# NewsGo — architecture

See [AGENTS.md](AGENTS.md) and [DEVELOPMENT.md](DEVELOPMENT.md) for workflow, [README.md](README.md) for operation, and [CURRENT_WORK.md](CURRENT_WORK.md) for the active draft PR.

## Runtime

The top masthead is rendered by the Homepage-owned `shared/ui/banner` package and its stylesheet served from NewsGo's own `/suite-ui/banner.css` endpoint. The dashboard opts into the **original Homepage two-shape teal ambient effect**, not radial gradients; all shapes are hidden for print. `suite-auth-status` is the existing verified Homepage account display hook, updated in place by NewsGo's browser logic. The module is pinned at build time; no browser dependency on a running Homepage CSS service is added. NewsGo's editorial hero, reader content and control layouts remain local.

The canonical button appearance is supplied by Homepage's nested Go module `github.com/richard-mauri/homepage/shared/ui` at the pinned version in `go.mod` (see [Homepage's UI contract](https://github.com/richard-mauri/homepage/blob/main/SUITE_UI_DESIGN_SYSTEM.md)). `internal/dashboard/dashboard.go` serves the module's embedded `ButtonCSS` at NewsGo's same-origin `/suite-ui/buttons.css` and allows it under `style-src 'self'`. The page keeps NewsGo's `--soft`, `--text`, `--line`, `--accent` tokens and layout rules; it must not maintain a second copy of the button component. This adds no runtime network dependency on Homepage.

- `cmd/newsgo/main.go`: service startup, catalog, server settings, listener, graceful shutdown; default `127.0.0.1:8084`.
- `internal/dashboard/`: UI, personal reading pipeline, Homepage account integration, administrator routes, diagnostics and operational settings.
- `internal/feeds/`: feed validation and fetching, URL safety, parsing and article normalization.
- ScraperGo is independent and provides article classifications, clean reading and thumbnails.

## RSS discovery identity and presentation

`POST /api/discover` validates a public HTTP(S) publisher page with the existing SSRF-protected client, probes a maximum of 24 candidate feed addresses, and returns at most eight distinct verified feeds. Feed titles come from each accepted RSS/Atom/JSON feed, with URL-based fallbacks for generic titles. Candidates are deduplicated by matching publisher-declared RSS channel Atom `rel="self"` links when present or by substantial overlap in article URLs (at least five common links and 80% of the smaller sample). Name equality alone never merges feeds. The browser may supply up to eight same-publisher existing feed URLs for comparison; a discovered equivalent offers actionable Unsubscribe for the existing record, with confirmation and re-discovery, rather than storing another duplicate. Actual stored subscription URLs and IDs are never automatically rewritten, migrated or deleted.

The Find Subscriptions browser UI groups discovered feeds by publisher and has one exclusion action per group; subscription controls use the shared button treatment. The browser keeps separate bounded eight-entry histories in `newsgo.recent.searches.v1` and `newsgo.recent.websites.v1`, held in `localStorage` and intentionally excluded from Homepage account profile synchronization. Search entries are saved on valid attempts; website entries only after a successful response with at least one discovered feed. Invalid/unavailable website discovery shows a nearby inline error. Histories survive ordinary browser/process restarts unless Safari website data is cleared; they do not have an automatic TTL.

## Reading and classification

NewsGo fetches selected RSS/Atom/JSON subscriptions in batches of at most eight. Each eligible article is checked using ScraperGo `POST /api/classify`; only confirmed `article` URLs appear in either normal or RSS metadata-only reading. Homepages, unreadable/unavailable/unknown outcomes, age-filtered articles and entries beyond feed caps are reported in the filtered/unprocessed audit. RSS metadata-only changes the displayed metadata and thumbnail source, not the classifier gate.

NewsGo's shared classification cache is persisted in the settings directory as `classification-cache.json` using atomic, permission-restricted snapshots. At startup, only valid, unexpired classifications are restored, and any rejected or expired entries are removed from the persisted snapshot through atomic compaction. Malformed, oversized and over-capacity cache files fail safely to a cold cache. Entries have absolute expirations at most 12 hours after classification, including across restarts and rebuilds. Normal-operation garbage collection is lazy on writes, without a periodic background cleanup timer. The cache is bounded to 2,048 entries, with expired/earliest-expiring eviction. The default administrator TTL is 720 minutes; a saved setting above 720 minutes is capped to 720 at runtime without rewriting `server-settings.json`. A configured zero disables caching. A cache write failure does not alter ScraperGo eligibility or account data. An existing stored TTL of 60 minutes remains in effect until the administrator changes the setting to 720 minutes. Previously cached absolute expirations are not extended retroactively. Readers can opt out of cache use in Reading Preferences without clearing shared entries. The per-reader Diagnostics view reports cache hits, misses, bypasses, disabled requests, configured TTL, feed durations, classification durations and render durations. ScraperGo has separate upstream caching not included in these counters.

## Homepage-only authentication and account persistence

Homepage provides **all live reader identity and account persistence**. The browser obtains a tab-scoped `#suite_token` handoff from Homepage and verifies it using `https://home.themauris.org/api/session/profile`. The token is removed from the visible URL and retained in `sessionStorage` while the original Homepage session is active, up to twelve hours. Following verified sign-in, NewsGo automatically retrieves the reader's account settings through Homepage's revisioned `/api/storage/newsgo` GET API, applies valid existing account data, and initializes the correct revision for explicit user-triggered Save Changes PUTs. If there is no account record, NewsGo does not create one until the user explicitly chooses Save Changes. A failed read or unsupported schema never authorizes overwriting existing data. Profiles remain isolated by Homepage identity. Browser-only preferences remain in browser `localStorage`. The legacy Account Sync panel, Save to account and Load from account buttons are removed. HTTP 409 conflicts suspend writes and retain browser state, with a visible account-status warning. No separate NewsGo token issuance or profile-sync login exists. The page includes a content-derived fingerprint in the `/personal.js` URL to prevent stale script reuse across development builds with the same semantic version. NewsGo shows only Homepage-asserted identity, with no app-specific renewal button or countdown. Homepage's Manage Tokens → Current session panel owns the timer, Renew and Disconnect. NewsGo stores the parent-bound handoff only in its tab. If an HTTPS direct visit to NewsGo has no handoff, it performs a one-time top-level navigation to Homepage's fixed `/launch/newsgo` route. Homepage alone reads the host-only cookie and issues a parent-bound handoff when it verifies a personal or Guest session. If an absent/expired/revoked parent yields the historical `#suite_mode=local` fragment, NewsGo **rejects that mode** and directs the user to Homepage sign-in or Guest authentication; it never enables anonymous reader access. A later direct visit rechecks Homepage in case the user has since signed in. NewsGo revalidates its profile against Homepage when the locally cached expiration is reached, because the parent may have been renewed while NewsGo remained open. The recovery navigation neither creates nor renews the parent login. A 401 clears the handoff; the server remains authoritative for privilege and per-user storage. NewsGo does not invoke `/api/handoff/extend-session`, `/api/handoff/renew` or `/api/session/renew`. The public HTML/assets support the sign-in recovery bridge only; every reader `/api/*` request requires Homepage-verified authorization.

NewsGo administrator endpoints `GET/PUT /api/admin/settings` and `POST /api/admin/classification-diagnostic` require server-side verification of the supplied Homepage bearer against Homepage's **fixed** HTTPS session-profile endpoint on every privileged request. The browser sends it in the dedicated `X-NewsGo-Homepage-Authorization` header. The Go verifier requires a valid bearer, a current expiry and the server-asserted `admin` role, with three-second timeout, no redirects and no persistent secret logging. An ordinary Homepage reader cannot administer NewsGo, regardless of browser UI manipulation. Reading Diagnostics is not privileged and remains browser-local.

There is no Server Sync token authentication, `/api/sync` route, separate token CLI, or migration path for old browser subscription formats. Current subscriptions are stored in the single `newsgo.subscriptions.unified.v1` browser registry. Homepage stores the optional account copy. Historical token and profile files, if still present on disk, are unused.

The browser's Diagnostics panel includes a **Homepage account synchronization** section reporting the most recent profile load/save operation, result, local timestamp and bounded error message. A failed Homepage load does not initialize an empty account, does not erase the local subscriptions and does not authorize a PUT; this diagnostic is separate from feed fetch and classification diagnostics.

NewsGo's direct-visit recovery first asks other NewsGo tabs for an already verified child bearer. If none is offered, a tab-scoped `sessionStorage` guard permits one recovery navigation through `/launch/newsgo`. A 401 for an existing child bearer can also use this bounded recovery; a second failed child verification does not start another bridge loop. Successful profile verification or explicit `#suite_mode=local` clears the guard. If session storage is unavailable, recovery fails closed to the sign-in prompt. In-flight focus/visibility checks do not open a competing prompt while navigation is pending. Homepage's own recovery bridge is the sole component allowed to issue a replacement bearer.

## Operational server settings

The dashboard exposes one **Settings** navigation item. Its Reading Preferences subpanel remains available to every reader, while the Admin Settings subpanel is shown only for a verified current Homepage administrator. The privileged server APIs continue to enforce authorization independently of the subpanel's visibility. The existing admin form and dirty-settings confirmation remain in that subpanel; combining navigation does not combine per-user and server-wide persistence.

Every top-level navigation button shares the `ui-button` and `ui-button-large` styling, with the same dark fill and neutral border whether selected or not. The mandatory UI convention and regression requirements are recorded in `DEVELOPMENT.md`.
This common resting appearance also applies to server-setting submit buttons, confirmation actions, subscription actions, and filtered-article tabs. Accent highlights are transient on hover or keyboard focus only, without changing button behavior or administrator authorization.

`internal/dashboard/settings_store.go` implements a dedicated, mutex-protected `SettingsStore` that reads and writes the existing revisioned `data/server-settings.json` atomically with restrictive file permissions. The CLI flag `-settings-dir` selects the directory (default `data`). Classification timeout/concurrency, per-feed cap, feed cache, classification-cache TTL and image settings use the current settings schema. Saving server settings updates active settings and clears both NewsGo's in-memory and on-disk classification cache. An administrator-saved TTL of zero disables NewsGo classification caching.

## Other diagnostics and safety

The administrator's fresh classification diagnostic is deliberately uncached. The localhost-limited feed-trace endpoint remains available. The client-side Download Article URLs export is placed in the Admin Settings panel, separate from the server settings form, and remains restricted by the browser to a live Homepage administrator session and completed all-subscriptions reading batch. It exports already displayed eligible URLs and does not create a server-side privileged download API.

Publisher URLs and responses are untrusted and subject to existing validation, request limits, timeouts and network safety rules. A browser role label alone is never an authorization decision. `cmd/scrapertrace` independently replays exported URLs through ScraperGo with sequential default operation, optional bounded four-worker concurrency, separate classification/read HTTP status and latency reporting.

`devbuild.sh` produces architecture-specific Mac binaries with a local build label. GitHub `main` remains the authoritative merged baseline. Use [CURRENT_WORK.md](CURRENT_WORK.md) for the current merged baseline and active review status.

## Filtered audit domain grouping (Issue #83)

Within each reason tab, browser-side `renderFilteredArticles` groups the existing filtered audit entries by `publisherScope(article.url)`, not display names or counts from feeds. Each normalized non-excluded domain gets exactly one `setUnifiedDomain(domain,false)` action alongside its count. Unknown hosts are grouped without a destructive action. `setUnifiedDomain` preserves the existing `confirmDomainRemoval` prompt and per-user exclusion/account storage workflow. Classification, counts, per-article links, admin fresh-classification details and the single-feed unsubscribe recommendation remain independent and unchanged. Grouping is presentation-only; no automatic exclusions.

## Cache-miss diagnostics (Issue #85)

The classification stats response includes cache misses split into absent and expired keys, plus miss outcomes for explicit `unknown`, `unavailable`, and invalid/failed upstream requests. The latter three are deliberately noncacheable. A named return and deferred miss accounting ensure failures and indeterminate results are counted once without storing raw URLs or mutating cache entries. The front end sums counts across feeds and displays them in Diagnostics → Latest read. Repeated requests with the same URL can yield repeat misses for noncacheable outcomes; cold/expired counters describe the entry at lookup time, not whether the request eventually produced a successful cache fill. Existing persistence, TTL, capacity, feed classification, and independent ScraperGo behavior are unchanged.

## Pre-classification reader domain exclusions (Issue #85)

The browser submits `excludedDomains:effectiveExcludedDomains()` with each bounded `/api/personal` batch, from the existing browser-local or Homepage-hydrated reader profile. The server validates the list and compares parsed normalized article URL hostnames, including subdomains but not sibling or suffix-lookalike hosts, before age filtering and ScraperGo classification/cache lookup. Matching articles get the existing `publisher exclusion` reason in the filtered audit without a ScraperGo request or a classification-cache miss. The server does not alter stored subscriptions, account data, global classification cache settings, or the feed fetch itself. Exclusion is a presentation/reader preference, not a security control; a caller can elect not to exclude a domain. Other reader clients that omit `excludedDomains` retain the old default behavior. Diagnostics remain request-based and exclude skipped entries from cache-hit-rate denominators.

## Optional Homepage activity telemetry (Issue #89, merged; verified identity added later)

`cmd/newsgo/main.go` creates an `ActivityReporter` only when explicitly configured with a URL and per-service secret. The reporter embeds `internal/dashboard/activity.js`, which sends a random tab-scoped identifier and coarse `visible`/`interacted` flags to a same-origin `POST /api/activity/ping`. That endpoint rejects cross-origin requests, unknown JSON, oversized input and malformed IDs, bounds the in-memory tab map to 5,000 and expires tabs after one hour. The reporter counts the rolling 2/5/15/60-minute windows and in-flight `/api/personal` requests, including feed and ScraperGo classification work within the synchronous request lifecycle. It sends only aggregate counts and timestamps to Homepage `POST /api/admin/activity/ingest` every 60 seconds using a server-only private key and fresh replay nonce. It is fail-open and has no authority over NewsGo sign-in or reader output. HTTPS or explicit loopback HTTP collector URL only; strict endpoint path, no credentials in URL and no redirects.

NewsGo verifies supplied Homepage identity server-side before classifying named/guest activity, distinguishing invalid bearer (401) from verification outage (503). No browser-supplied role flag is trusted. Disconnected/scraper-queued work is out of scope and should be measured by ScraperGo's independent reporter. The Homepage dashboard labels a NewsGo reporter as unknown if no fresh report arrives, not idle.

### Reproducible two-process local integration acceptance (Issue #89)

`scripts/activity-integration-test.sh` drives the actual NewsGo binary and a previously built isolated Homepage candidate with a shared ephemeral environment-only `HOMEPAGE_ACTIVITY_KEY_NEWSGO`. It refuses to operate without an existing disposable Homepage test root, existing isolated administrator registry, and free loopback ports 8788/8085. It creates a fresh NewsGo settings directory, deliberately replaces ScraperGo's test reader destination with `http://127.0.0.1:1` to avoid affecting the live reader, and does not invoke production launchers. Both children are tracked by PID and stopped when the harness exits. NewsGo's one-minute aggregate report should produce a new `newsgo` activity entry in the same Homepage admin UI already validated on Safari. This verifies protocol cooperation and browser heartbeat, but **not** actual ScraperGo work or production tunnels. A Go unit test checks the harness's Bash syntax and key isolation invariants; genuine Mac/Safari proof remains an owner test.

## Shared authentication boundary — Issue #110 candidate

The NewsGo executable wraps the dashboard with `dashboard.NewNewsGoAuthGate().Protect(app)`. The middleware applies the Homepage-owned, immutable-pinned `github.com/richard-mauri/homepage/shared/auth` `Guard` to **all** `/api` and `/api/*` requests, including unknown/future routes. Every request carries a strict 64-lowercase-hex child bearer in its normal Authorization header; NewsGo checks it via the fixed Homepage HTTPS `GET /api/session/profile`, using `Origin: https://newsgo.themauris.org`, a bounded response and HTTP timeout without redirects. The module allows verified named users/admins and temporary Guests for app access, rejects anonymous and invalid/revoked/expired identities (401), and denies upstream errors (503). Caller-supplied role headers and the optional activity reporter never authorize access. Existing admin-only endpoints retain a **second** check through their established Homepage administrator verification; the common gate alone is not administrator authorization.

`GET /`, `/personal.js`, `/activity.js`, local suite CSS/JS, portrait and `/health` are public bootstrap assets, because a fresh browser receives its bearer through an URL fragment after Homepage handoff. The static shell contains no requested feed results; CSS hides the interactive `.suite-content` until an authenticated profile is confirmed, and each reader/discovery/admin API browser fetch adds the same verified bearer. API authorization remains server-side regardless of CSS. A legacy `#suite_mode=local` response is rejected and directed back to Homepage; a revoked bearer or verification outage hides the interface. Existing browser history and account settings are not cleared by these transitions.

**Compatibility:** The shared module is introduced in Homepage [draft PR #61](https://github.com/richard-mauri/homepage/pull/61) and pinned by exact immutable Go version and checksums. This NewsGo PR does not modify Homepage, the shared UI module, CORS, cookie lifetime, per-user settings, automatic syncing, ScraperGo or the server-settings storage schema. The two services require coordinated owner testing before separate promotion. The shared verifier injection API is sufficient for this phase; no Homepage framework amendment was necessary.

## Explicit user settings persistence — Issue #112 candidate

NewsGo now uses an in-memory `pendingReaderSettings` map as the sole staging area for subscriptions (`unifiedKey`), publisher/article exclusions, age, lead count and all-subscriptions mode, classification cache, RSS metadata-only, and last reading selection. User events call `stageReaderSetting` and update the live UI but do **not** write those keys to `localStorage` or call Homepage. The shared-style reader toolbar provides one `Save Changes` action. On click, `commitReaderSettings` validates the complete `accountSnapshot`, transactionally commits staged local keys with rollback on quota/write errors, then for a verified personal user performs one revisioned Homepage `PUT /api/storage/newsgo`. A Guest commits local settings only. An error retains unsaved staged edits or a per-user pending account snapshot, re-enables Save Changes, and never schedules a timer-based retry. Successful saves show `Settings saved`, with newer edits independently staged. A Safari `beforeunload` guard covers pending edits and pending account retry, alongside the existing independent admin form guard.

The prior automatic account-save debounce (650 ms), 30-second background retry and new-account automatic initialization have been removed. Homepage account preferences are still loaded on valid sign-in, but a slow account GET must not overwrite staged user edits, and a failed explicit account write is retained under an owner-specific `newsgo.account.unsynced.v1.<encoded-owner>` browser key containing its validated snapshot. A later verification as **that same owner** can restore and retry it; another identity cannot take over its pending snapshot. The pre-existing per-user revision/409 guard and Homepage's actual storage authorization remain authoritative. No schema change to the account payload and no migration of private subscription records. Browser-local recent-search and website discovery histories intentionally retain their existing immediate write/clear semantics; they are not included in the account profile. Admin `Save Server Settings` remains separate, including its existing own unsaved form warning.

Issues #110 and #112 are both implemented in the same branch `auth/110-verified-suite-access` and draft PR #111 for coordinated acceptance of authentication and saving. The shared Homepage framework needs no change to support manual commits.


## Restricted NewsGo–ScraperGo machine classification identity (draft)

A server-side `SUITE_NEWSGO_SCRAPERGO_CLASSIFY_TOKEN` contains exactly 64 lowercase hexadecimal digits and is provisioned to both independent processes outside Git. NewsGo's classification pipeline and its admin diagnostic send `Authorization: Service <token>` exclusively to `POST /api/classify` over HTTPS (or loopback HTTP in tests); their HTTP clients reject redirects. ScraperGo performs a constant-time comparison against its configured token and routes a matching service request only to the allowlisted classification POST or thumbnail GET handler. Service authentication is not a Homepage personal/Guest login, does not issue a user identity or profile, and cannot access `/api/read`, `/api/article-image`, PDF, telemetry, identity, diagnostics or other APIs. All other APIs continue to require freshly verified Homepage bearers. Missing/malformed credentials cannot grant a machine identity. No account schema, persistence, UI, shared Homepage auth module or publisher extraction changes.

## Reading navigation versus staged preferences

The NewsGo browser remembers `newsgo.lastReadingSelection.v1` immediately in localStorage when choosing a subscription or All Subscriptions, or clears it when the selection is invalidated by unsubscribe. This is operational navigation state and does not enter `pendingReaderSettings`, trigger a Homepage account PUT, or activate `beforeunload` unsaved-change protection. Other preferences and subscription/exclusion edits retain explicit Save Changes, including retry semantics and account isolation. A subsequent explicit account save can include the current reading selection in the profile snapshot; no navigation-triggered account write occurs. Storage exceptions are caught so reading remains usable. CI executes the embedded navigation function and checks both selector paths and save staging independently.

## Initial feed-refresh authorization ordering

The browser may restore `newsgo.lastReadingSelection.v1` before the asynchronous Homepage `/api/session/profile` request completes. `refresh()` does not call NewsGo `/api/personal` until `homepageIdentity`, a child bearer, and its unexpired verifier deadline are present. A pre-verification reading request records `refreshPendingAfterAuth` and displays a waiting status; successful `checkHomepageSession()` reissues that request once after marking the UI verified. Verification failures continue to fail closed; they do not send anonymous feed requests or clear private settings. If the user has no selected feed, no automatic fetch is scheduled. The existing `refreshSequence` prevents stale in-flight results from replacing newer ones.


## Protected thumbnail integration — Issue #114 draft

The existing Homepage guard protects this endpoint. The proxy validates article URL/width and upstream destination, prevents redirects, limits concurrency and image response size/types, and uses **the same private `SUITE_NEWSGO_SCRAPERGO_CLASSIFY_TOKEN` already used for classification**. ScraperGo PR #148 checks the same service credential with independent method/path allowlists: `POST /api/classify` and `GET /api/thumbnail` only. No additional token is needed, and no bearer/credential is exposed to the browser. ScraperGo's SSRF/media behavior and RSS metadata-only mode remain unchanged.

## Server-only classification loopback separation — Issue #116 extension

`State.reader` remains the public ScraperGo browser-reader URL and the stable namespace for classification cache keys, including persisted entries. `State.classificationBackend` is an optional explicit-IP loopback HTTP origin configured by `-classification-backend`; it changes only the outgoing network destination of normal classification POST and uncached admin classification diagnostic. ## Thumbnail queue, timeout and redacted browser diagnostics — Issue #116 candidate

NewsGo has a process-wide mutex/notification admission gate that checks a bounded, administrator-configurable active thumbnail limit. The gate waits at most `queueWaitSeconds` before allocating a slot; **only after admission** does the independent `upstreamTimeoutSeconds` budget begin. A queue timeout or upstream timeout yields HTTP 504, distinct from the external request/format failure 502 and Homepage authentication-verification 503. Response headers `X-Thumbnail-Queue-Ms`, `X-Thumbnail-Upstream-Ms`, `X-Thumbnail-Outcome` and `X-Thumbnail-Active-Limit` contain bounded operational observations but no article URL, token or identity. The browser collects only its current briefing's observations in memory and displays aggregate queue/upstream mean and p95 plus counts in Diagnostics → Thumbnail Performance. The diagnostics are not a persistent, global telemetry store. Canceled requests may not return headers.

The existing `server-settings.json` schema gains an optional `thumbnail` section, using safe defaults when absent on legacy files. Administrator PUT retains existing revision and server-side auth checks; successful saves change subsequent admission decisions without replacing in-flight admission state. Limits are 1–16 concurrent requests, 1–30 seconds queue wait and 2–30 seconds upstream timeout. Security bounds and localhost routing are unchanged. An in-progress request keeps the limits captured on admission; a decreased concurrency setting never forcibly cancels existing requests.


### Thumbnail origin attribution on failures

The protected thumbnail handler adds a constant `X-NewsGo-Thumbnail-Proxy: v1` response marker before request validation, so its own successful images and error responses (including queue-generated 504 and upstream errors) carry the marker. This identifier is independent of article URL and credentials. The browser only classifies `X-Thumbnail-Outcome` as NewsGo-produced when the marker is present, prefixes those categories `proxy_`, and otherwise records `unattributed_http_<status>`. Absence of a marker does **not** prove Cloudflare or a particular intermediary generated the response: authentication middleware, edge layers, network behavior or header removal may prevent observation. Queue/upstream timing summaries use only headers paired with the marker. Do not attach service credentials, article URLs or per-user identifiers to diagnostics.


### Browser-local plain-text diagnostics export

The Diagnostics panel has a user-initiated `Download Diagnostics (.txt)` button. `diagnosticsTextReport()` explicitly reads only the numeric/aggregate Latest Read, Timing and Thumbnail Performance view nodes already rendered in the browser; it omits source-identifying notes and the raw feed inspector. Optional thumbnail tuning settings come solely from the administrator settings already present in memory, subject to `mayAdminister()`. The exporter never serializes the page or a server response, does not include tokens, URLs or identities, and does not make a network request. An in-memory `Blob` is downloaded via a temporary object URL, which is subsequently revoked. The report has an ISO UTC timestamp, explains the limited scope and distinguishes `proxy_*` from unattributed HTTP outcomes. Report values reflect the current browser's last completed read and may be unavailable before the first read.


### Correlated thumbnail request-path logging — Issue #116

`NewNewsGoAuthGate().Protect(app)` wraps only `/api/thumbnail` requests with a tracing layer **outside** the existing Homepage authentication guard. That layer generates a process-local, monotonically increasing opaque request ID and sets `X-NewsGo-Request-ID`, replacing any untrusted request ID supplied by a client. It observes the final HTTP status (including guard 401/503, handler 400/502/504 and canceled requests) and whether `X-NewsGo-Thumbnail-Proxy: v1` was set by the inner handler. For non-successes, it writes a redacted `THUMBNAIL boundary` line to the process logger. The handler independently logs its non-successes as `THUMBNAIL handler` with the same ID from request context; never log query strings, article URLs, bearer/service credentials, identities or headers. Queue and upstream values are accepted only as unsigned integers, otherwise logged as `-`. Successful handler-marked requests increment an atomic, process-local success count, logged once per 100 successes rather than per request. The wrapper does not alter authentication decisions, queue admission, upstream timeouts, media validation, or route selection; no new persistence or external telemetry endpoint is added. A browser-side 502/504 without a NewsGo handler marker is still of *unknown origin*: use request IDs/temporal correlation to distinguish a guard response from a response that never reached this process. Application log output and rotation are controlled by the existing launcher (which currently truncates its redirected log on restart).


### Authenticated progressive thumbnail batching

The protected `POST /api/thumbnail/batch` endpoint is routed inside the existing Homepage-verified API guard and accepts only a JSON object `{"urls":[...]}` with **1–20** separately validated public article URLs, each at most 2,048 bytes and the body capped at 46,000 bytes. Input is completely validated before any request is started; invalid/oversized input is rejected. A maximum six-worker batch pool submits each image to the existing `serveThumbnail` logic via internal in-memory response recording; that logic retains current strict URL/width, media type, 3 MiB, no-redirect, auth credential, queue admission and upstream deadlines. Server results are streamed as `application/x-ndjson`, one record per completed item with zero-based index, HTTP status, outcome, queue/upstream timing (if available), MIME, and base64 image bytes only for successes. Workers observe the parent request context; the response stream ends when all workers complete or on cancellation/write failure. The batch's sanitized log includes a generated request ID, counts and duration; inner handler failures use IDs in the form batchID.itemIndex. This protocol intentionally requires a bounded payload and imposes no new caching or persistent storage. Base64 encoding increases wire size, and NDJSON buffering intermediaries may affect progressive delivery; owner Safari acceptance must check actual behavior.

The normal-mode Safari renderer groups article images into **sequential batches of 20**, parses streamed NDJSON incrementally and maps each indexed item to the corresponding existing image element, with per-image successful-load/error diagnostics and object-URL cleanup. Rerender aborts the active batch and invalidates its generation; the previous single-image fetch remains the fallback only for a 404/405 on the batch route, not for unrelated upstream errors. RSS metadata-only external images retain their original behavior. Browser diagnostics count batch HTTP requests separately from per-image results. The batch design does not itself change the global admission gate or guarantee no timeouts if other users compete for the shared worker limit.
